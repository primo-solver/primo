# Reporting security issues

Use GitHub's private vulnerability reporting on this repository for security
vulnerabilities: open **Security → Report a vulnerability**. It must be enabled
by the maintainer before public launch. Do not put sensitive details in a public
issue. If private reporting is unavailable, ask a maintainer for a private
channel without disclosing the issue or attaching confidential input.

For ordinary solver correctness bugs, use the public bug template with a
shareable minimized example. Include the exact revision, command, expected and
actual results, relevant stderr, and limits. Wrong answers and invalid models
are correctness failures even when they do not create a security vulnerability.

The development branch is the supported research version. There is no promise
of maintained historical releases, response times, or suitability for executing
untrusted workloads. Maintainers will acknowledge reports, reproduce them, and
coordinate fixes and disclosure with the reporter.
